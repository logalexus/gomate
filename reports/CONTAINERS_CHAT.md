# Контейнеры, логи и анонимный чат

Проверено 14 ноября 2026 на Kali `192.168.56.103`. Обновлённые app и discovery работают на http://192.168.56.103:65000. Инструкция: [CONTAINERS_CHAT.md](../docs/CONTAINERS_CHAT.md).

## Реализовано

- Отдельная вкладка контейнеров: поиск, фильтр состояния, страницы, статус и порты; запуск, остановка, перезапуск, пауза и продолжение. Остановка, перезапуск и пауза требуют подтверждения с именем контейнера. Управление собственными app/db/discovery блокируется сервером.
- Логи с выбором контейнера, периода и числа строк, поиском, stdout/stderr, LIVE и просмотром полного текста строки. Ограниченные снимки, отмена запросов и виртуализация списка ограничивают использование памяти и DOM. Фильтрация работает внутри загруженного фрагмента; промежуточный вывод между снимками может быть пропущен.
- Общий чат без персональных аккаунтов: анонимное имя браузера, отправка и история, обновление у других участников, сохранение сообщений в PostgreSQL. Лимиты отправки, пагинация и виртуализация; история до 7 дней / 10 000 сообщений, до 500 сообщений в браузере. Общий пароль доступа к gomate сохраняется.

Docker socket остаётся только у шлюза discovery. API разрешает фиксированный набор действий и ограничивает параллельное чтение логов; произвольные команды Docker не доступны. Подробные ограничения и поведение описаны в инструкции.

## Функциональные проверки

`python3 scripts/test-integration.py` прошёл с `go test -race ./...` на отдельной БД `gomate_test`; `go vet ./...` прошёл. Проверены Docker multiplex/TTY, ограничение и очистка строк, авторизация шлюза, защита контейнеров, допустимые действия, подтверждение и origin запросов. Тесты чата проверяют независимые браузеры, повторную отправку без дублей, конкурентную запись, курсоры истории, ограничения частоты и очистку истории. Production frontend и Docker image собраны; Vite предупреждает о размере JS chunk.

Браузерный функциональный тест (`ui-operations.json`, локальный артефакт) прошёл:

- На изолированном контейнере выполнены start/stop/restart/pause/unpause; управление защищённым gomate отклонено.
- Проверены поиск логов, stdout/stderr, TTY и отображение HTML как текста.
- При снимке 2000 строк в DOM было 30 строк; в проверке истории чата — 16 элементов сообщений.
- Проверены 14 независимых браузерных контекстов и 122 сообщения, двустороннее обновление, история и сохранение сообщений/анонимного имени после перезапуска app. Ошибок JavaScript нет.

Этот тест выполнялся до последней правки сброса прокрутки при смене маршрута/вкладки. Финальный образ с этой правкой проверен совместным прогоном ниже; полный сценарий lifecycle после неё повторно не запускался.

## Трафик вместе с браузерами

Генератор находился на `192.168.56.102`, моки слушали реальные порты Kali `192.168.56.103`: HTTP 18080, TCP 19090, gRPC 15051. Capture работал на `eth1`; SSH-туннель для данных не использовался. Запланировано 100 запросов каждого unary-протокола по 10 запросов/с (суммарно 30/с около 10 секунд), дополнительно 10 streaming RPC по 5/с с тремя ответами каждый.

| Прогон | Браузеры | Результат |
| --- | --- | --- |
| Первый совместный (`kali-operations-cold-start.json`, локальный артефакт) | 4 просмотра логов + 4 чата | Не прошёл: генератор не запустил 1 streaming RPC. Все 327 фактически полученных ответных сообщений сохранены. |
| Повторный совместный (`kali-operations-smoke.json`, локальный артефакт) | Те же 8 контекстов, задержка 5 с перед генерацией | Не прошёл: генератор не запустил по 1 HTTP/TCP/gRPC запросу. Все 327 фактически полученных ответных сообщений сохранены. |
| Контрольный без браузеров (`kali-operations-baseline.json`, локальный артефакт) | 0 | Прошёл: все 310 запланированных RPC/запросов выполнены, 330 ответных сообщений сохранены. |

Генератор пропускает запуск, если отстаёт от расписания более чем на 100 мс. Совместные прогоны не достигли заданного профиля; их результаты сохранены как неуспешные. Устранение пропусков в контрольном прогоне само по себе не доказывает причину задержек.

В этих прогонах capture/flow/queue/write drops, ошибки БД и декодирования — 0. Проверка браузеров при повторном совместном прогоне (`ui-operations-load.json`, локальный артефакт): 53 успешных ответа API логов, ошибок HTTP и JavaScript нет, по 30 DOM-строк у четырёх просмотрщиков; после перехода на другую страницу polling логов прекращается. Четыре клиента чата в этом прогоне только читали историю. Общий результат теста остаётся `passed: false` из-за генератора.

Это короткие функциональные проверки и проверки регрессий. Длительная работа, пиковая нагрузка и одновременный активный трафик от 50 команд по 4 человека ими не подтверждены. Kali имеет 12 vCPU / около 24 GiB; app и БД ограничены каждое 1 CPU / 2 GiB, discovery — 0.25 CPU / 64 MiB, каждый mock — 1 CPU / 128 MiB. Это не приёмка на общей машине 8 CPU / 16 GiB.

## Повторение

Нужны разрешённый Kali-стенд, SSH по ключу, `.cache/kali.env`, локальный `bin/mock` и установленный Playwright/Chromium. Функциональный браузерный тест намеренно один раз перезапускает app; используйте тестовый экземпляр. Скрипт создания fixtures откажется перезаписывать существующие контейнеры с теми же именами.

```sh
python3 scripts/test-integration.py
.tools/go/bin/go vet ./...
bash scripts/operations-fixtures.sh up
node tests/browser/operations.cjs
node tests/browser/operations-load.cjs
bash scripts/operations-fixtures.sh down
python3 scripts/remote-bench.py --count 100 --rps 10 --tag operations-baseline
```

После теста сообщения с его уникальным `run` остаются в чате до удаления/retention. Скрипт `down` удаляет только два fixture-контейнера. Перед повторением сохраните существующие JSON-отчёты: скрипты используют фиксированные имена файлов. Новые снимки браузерных тестов сохраняются в JPEG с качеством 35.
