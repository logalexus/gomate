# Удаление сервиса из фильтров — 15 ноября 2026

Причина: `Navbar.editService` присваивал выбранный сервис и сразу открывал
модальное окно в одном Vue tick. Обработчик `ServiceModal.@show` читал старый
`initialService = {}`: поля были пустыми, DELETE уходил на `/api/service/null`.
Воспроизведено на инстансе с перехватом запроса, без удаления рабочих сервисов.

Теперь открытие ждёт обновления props через `$nextTick`, как при редактировании,
так и при добавлении. Подтверждение показывает имя и порт; повторный клик блокируется.
После успешного удаления выбранного сервиса интерфейс переключается на «Все сервисы»,
сохраняя фильтры меток. При ошибке настройки остаются открыты для повторной попытки.
История сессий не удаляется; backend удаления не изменён.

Проверки:

- `node tests/browser/service-delete.cjs`: первый выбор сервиса, смена сервиса,
  создание → редактирование, сохранение, отмена, ошибка и повторное удаление,
  сохранение меток, тёмная тема 1366px и светлая 375px.
- `node --test tests/browser/traffic-filters.test.mjs`: 3/3.
- `npm run build`: успешно.
- Тот же браузерный сценарий на развёрнутом UI с подменённым API:
  `reports/service-delete-live.json`; реальные записи не выполнялись.
- Проверка настоящих данных инстанса: имя/порт в настройках и подтверждении,
  отмена удаления, неизменность сервисов и работающий захват —
  `reports/service-delete-instance.json`.

Деплой: frontend поверх текущего образа приложения, backend сохранён;
подробности и образ отката в `reports/service-delete-deployment.json`.
Пересоздан только app; остальные контейнеры не перезапускались.
