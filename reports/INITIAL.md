# Первый рабочий срез и локальные проверки

Дата: 2026-11-14. Это промежуточный результат; требования полного переноса из PLAN.md ещё не выполнены.

Реализован путь LIVE → TCP reassembly → шаблоны → PostgreSQL → Vue UI. Бэкенд собирается в контейнер; API, очереди и память имеют ограничения. Исходный frontend сохранён с изменениями транспорта событий, сборки и просмотра страниц. Реальная HTTP/2/gRPC-интерпретация, lookback, streaming matching через границы частей и миграция истории пока не реализованы.

## Локальная среда

Linux 6.8.0-138-generic, KVM, 8 доступных CPU, около 7,8 GiB RAM. На машине работают посторонние приложения. LIVE-тест выполнен в отдельной Docker-сети: анализатор 1 CPU / 512 MiB, HTTP fixture 1 CPU / 128 MiB, PostgreSQL 1 CPU / 2 GiB. Генератор на той же машине, поэтому ограничивает достижимую нагрузку. Это не согласованный приёмочный стенд 8 CPU / 16 ГБ с игровыми сервисами.

## Выполненные проверки

- Go tests с `-race`: TCP reordering/retransmit, открытое соединение до FIN, pure ACK, лимит SYN-потоков, неполный midstream capture, повреждённый UDP application payload, Unicode/regex/байтовые шаблоны, конкурентная замена каталога, восстановление writer после ошибки, batching с медленной записью.
- PostgreSQL integration: idempotent batch, pagination, favorites/retention, API и auth. Тесты используют отдельную `gomate_test`.
- `go vet ./...`; сборка frontend через Vite; browser smoke в Chromium: список, payload, подсветка, hex, pause/resume и фильтр. Скриншот (`browser-smoke.png`, локальный артефакт).
- Пятисекундный fuzz packet admission: 17 212 выполнений без обнаруженного crash; это короткая проверка, а не исчерпывающий fuzzing.
- Java backend исходной ревизии собран на JDK 17 / Gradle 8.1. Нагрузочное сравнение с запущенной Java-версией не проведено. `scripts/RegexProgress.java` воспроизводит непродвижение позиции при regex нулевой длины; связь с реальным историческим зависанием пользователя не установлена.

## Короткая нагрузка

| Прогон | Успешные ответы генератора | Уникальные ответные маркеры в БД | Потери анализатора | Ограничение вывода |
| --- | ---: | ---: | --- | --- |
| 50 RPS × 10 с | 500 | 500 | Не наблюдались | Smoke; проверены SQL-количества |
| 200 RPS × 10 с | 2 000 | 2 000 | 0 по capture/flow/queue/write | Полный отчёт (`live-200rps-10s.json`, локальный артефакт) |
| Цель 500 RPS × 10 с | 4 992 | 4 992 | 0 | Генератор не отправил 8 запланированных запросов; отчёт (`live-500rps-10s.json`, локальный артефакт) |
| Цель 1 000 RPS × 10 с | 9 943 | 9 943 | 0 | Генератор не отправил 57 запросов; это не подтверждение устойчивых 1 000 RPS; отчёт (`live-1000rps-10s.json`, локальный артефакт) |

Первые прогоны 1 000 RPS выявили ошибки: завершающий ACK создавал пустые потоки, а постоянный timer при медленных commit приводил к маленьким batch. Исправления покрыты регрессионными тестами. Неуспешные результаты сохранены как `live-1000rps-10s-before-*.json`; метаданные теперь записываются bulk-запросом, payload через COPY. Полного профилирования ещё не было.

После паузы выделенного PostgreSQL на 5 секунд readiness вернулся с 503 на 200, start time процесса анализатора не изменился; все 1 171 фактически отправленных ответа обнаружены в БД. Генератор не выдержал полное расписание 1 200 запросов, поэтому это проверка восстановления, не производительности. Отчёт отказа БД (`fault-smoke.json`, локальный артефакт).

## Что эти результаты не доказывают

Нет шестичасового soak, оценки влияния на настоящие игровые сервисы, тестов всех протоколов/ошибок и сопоставимого Java/Go baseline. Нет оснований заявлять двукратное ускорение или готовность к соревнованиям. Границы текущего прототипа перечислены в [README.md](../README.md).

Стенд Kali с отдельными HTTP/TCP/gRPC-моками развёрнут по разрешению пользователя. Его результаты опубликованы отдельно в [KALI.md](KALI.md) и `kali-*.json` и не подменяют локальные измерения.
