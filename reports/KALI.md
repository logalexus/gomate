# Развёртывание и прямой трафик на Kali

Дата: 2026-11-14. Развёрнуто по разрешению пользователя в `~/gomate-test` на `192.168.56.103`. Контейнеры оставлены работающими.

## Схема

`devops 192.168.56.102 / enp0s8 → общая сеть VirtualBox → Kali 192.168.56.103 / eth1 → Docker published ports → mock containers`

Данные нагрузки **не идут через SSH**. SSH используется для управления и проверки БД. После объединения VM в общую сеть пробросы через SSH/VirtualBox для тестовых сервисов не создавались.

- UI: `http://192.168.56.103:65000`, логин `packmate`, пароль `WEB_PASSWORD` в `~/gomate-test/.env`; локальная копия `.cache/kali.env` исключена из Git.
- HTTP: `192.168.56.103:18080`; raw TCP: `192.168.56.103:19090`; gRPC: `192.168.56.103:15051`. Все три Docker-порта опубликованы на `0.0.0.0`.
- Gomate захватывает только `eth1` до Docker NAT; сервисы зарегистрированы с опубликованными портами. `[LOCAL_IPS]=192.168.56.103`.
- Приложение и PostgreSQL имеют ограничения по 1 CPU / 2 GiB; моки — по 1 CPU / 128 MiB. Kali предоставляет 12 CPU и около 24 ГБ RAM, исходная VM — 8 CPU и около 8 ГБ. Приёмочный профиль 8 CPU / 16 ГБ на общей машине пока не воспроизведён.
- Пакеты внешней сети подтверждены [tcpdump](kali-wire-proof.txt); в БД указаны source `192.168.56.102` и server `192.168.56.103`.

Состав контейнеров, image IDs, лимиты и состояние сохранены в [kali-deployment.json](kali-deployment.json). Инструкции запуска — [deploy/kali/README.md](../deploy/kali/README.md).

Клиентские задержки в отчётах относятся к вызовам сервисов, а не к задержке публикации в UI. Прогоны имеют разные длительности и проводились без контроля всей нагрузки гипервизора: по ним нельзя вычислять влияние анализатора в процентах или объявлять достигнутую устойчивую пропускную способность. Необходим отдельный контролируемый benchmark генератора, сети и моков. Причина пропусков расписания/высоких задержек окончательно не установлена.

Браузерная проверка удалённого UI прошла: список сессий, просмотр payload, подсветка маркера, hex, pause/resume и фильтр по шаблону; JavaScript exceptions не обнаружены. [Скриншот](kali-browser.png).

gRPC-мок использует настоящий HTTP/2 и protobuf, включая streaming. В текущем gomate проверено **сохранение TCP-байтов с gRPC-маркерами**, а не декодирование RPC в отдельные сущности UI. Семантический HTTP/2/gRPC-разбор остаётся работой по PLAN.md.

Длительная шестичасовая приёмка не выполнялась. Результат этого этапа — работающий удалённый стенд, реальный сетевой путь между VM и воспроизводимые проверки. Полный перенос ещё не завершён.

Обновление: этот документ описывает первоначальную raw-версию. Новые декодеры, lookback, импорт и UI проверены отдельно в [FEATURES.md](FEATURES.md); прежние отрицательные нагрузочные результаты сохранены.
