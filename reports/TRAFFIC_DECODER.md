# Декодер трафика

Добавлено окно разбора блока/выделения: автоматическое распознавание JWT, Base64/Base64URL, URL, HEX и JSON, а также ручные декодеры. Можно переносить результат или его выделение во вход, возвращаться назад, копировать текст, отдельно читать header/payload JWT. Исходные пакеты и серверный поиск шаблонов не изменяются.

Инструкция и пределы: [TRAFFIC_DECODER.md](../docs/TRAFFIC_DECODER.md). Для интерфейса применён локальный [ui-ux-pro-max](../.agents/skills/ui-ux-pro-max/SKILL.md): подписи полей, состояния/ошибки, отмена, клавиатура, ограничение работы основного потока, светлая/тёмная темы и узкий экран. Vue 3-специфичный `v-memo` из подсказки навыка не применялся: проект использует Vue 2.7.

## Изоляция и ограничения

Обработка запускается по кнопке в отдельном Web Worker; LIVE не ставит задачи декодирования в очередь. Один worker на открытое окно, отмена при изменении данных/закрытии и тайм-аут 2 секунды. На вход до 65 536 UTF-16 единиц, результат до 256 KiB; JSON глубиной до 32, автопоиск до 16 результатов / 512 проб. Бинарные результаты не превращаются в текст с потерей байтов; показан явно ограниченный HEX.

Тест максимального входа выявил квадратичное поведение первого регулярного выражения поиска JWT на строке из 65 536 `a`: около 3,1 секунды. Поиск заменён линейной токенизацией с последующей проверкой частей. После исправления весь тест ограничений занимал около 40 мс в Node на этой машине. Это регрессионная проверка, не гарантия времени на любом устройстве.

## Проверки

`node --test tests/browser/traffic-decode.test.mjs` — 5 тестов прошли. Покрыты UTF-8/Base64URL/padding, невалидные символы и завершающие биты, бинарные данные, JWT/JWE и timestamps, URL против form-кодирования, HEX/JSON escapes, вложенный Base64, поиск в HTTP/JSON, ограничение размера/глубины/результатов и длинный однородный ввод.

Production frontend и Docker image собираются; сохраняется предупреждение Vite о размере основного JS chunk. Декодер worker вынесен в отдельный asset. Backend для этой функции не менялся; новая миграция БД не требуется.

Браузерный сценарий `node tests/browser/traffic-decode.cjs` **прошёл**. Он отправляет один HTTP-запрос с синтетическими Base64/JWT через реальную сеть `192.168.56.102 → 192.168.56.103:18080`, находит сохранённый входящий блок и проверяет UI на Kali. Результат: [ui-traffic-decode.json](ui-traffic-decode.json). Проверены автоматический Base64/JWT, выделение payload, вложенный Base64 и возврат, ручной form URL, ошибки без старого результата, HTML как текст, бинарный HEX, лимит входа, выделение в исходном пакете и неизменность захваченных байтов. Ошибок JavaScript нет. 65 536 символов обработаны за 118 мс от нажатия до результата в данном прогоне.

Проверка тайм-аута/отмены использует подмену Worker только в тестовом браузере; реальные worker проверяются на остальных шагах. На ширине 375 px у окна нет горизонтального переполнения. Контраст текста входного поля: 8,18:1 в светлой и 14,42:1 в тёмной теме. Проверены Escape и возврат фокуса на кнопку исходного блока. Скриншоты не создаются.

Первый браузерный прогон выявил потерю клавиатурного фокуса при отключении кнопки на время работы: Escape не доходил до обработчика модального окна. Исправлено перемещением фокуса во входное поле при запуске/отмене и явным возвратом к кнопке блока. [Результат до исправления](ui-traffic-decode-before-focus-fix.json) сохранён.

Тест не создаёт/изменяет сервисы, шаблоны или контейнеры. Каждый запуск оставляет одну синтетическую HTTP-сессию в истории до штатной retention. Повторный запуск перезаписывает JSON-отчёт; перед повторением сохраните его при необходимости. Этот сценарий не является новой приёмкой соревновательной нагрузки.
