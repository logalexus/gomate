# Форматирование чата

Изменение добавляет Markdown в общий чат: блоки кода с необязательным названием языка и копированием, inline code, жирный/курсив/зачёркнутый текст, списки, цитаты, ссылки и таблицы. Панель форматирования работает с выделением; предпросмотр использует тот же компонент, что отправленные сообщения.

Внутри блока кода Enter вставляет новую строку. Вне блока Enter отправляет, Shift+Enter вставляет строку; Ctrl/⌘+Enter отправляет из поля ввода. Исходная разметка хранится в прежнем поле сообщения: миграции БД нет, лимит 2000 символов сохранён.

Рендерер `markdown-it@15.0.3` не принимает HTML и не загружает внешние изображения. HTTP(S)/mailto-ссылки открываются с `noopener noreferrer`. Код и название языка экранируются; подсветка синтаксиса не включена. Длинные блоки прокручиваются внутри сообщения, список чата остаётся виртуализированным; Markdown пересчитывается при изменении текста компонента.

## Проверки

- `node --test tests/browser/chat-markdown.test.mjs`: 4 теста прошли — форматирование, сохранение пробелов, экранирование HTML/метаданных блока, опасные URL, длинные и незакрытые блоки, определение блока у курсора.
- `npm --prefix web run build` и Docker production build прошли. Сохраняется предупреждение Vite о размере основного JS chunk.
- `node tests/browser/chat-formatting.cjs`: прошёл на развёрнутом Kali в двух браузерных контекстах. Проверены панель с выделением, предпросмотр, горячие клавиши, получение форматированного сообщения другим участником, копирование кода с отступами по HTTP, безопасное отображение, сохранение исходной разметки/перезагрузка и отсутствие горизонтального переполнения на ширине 390 px. Ошибок JavaScript нет. Результат (`ui-chat-formatting.json`, локальный артефакт).

Первый запуск браузерного теста остановился на слишком строгом сравнении пробелов вокруг цитаты: Markdown добавляет перевод строки перед её абзацем. Сравнение исправлено; точное сравнение пробелов внутри кода сохранено. Первый запуск (`ui-chat-formatting-attempt1.json`, локальный артефакт).
