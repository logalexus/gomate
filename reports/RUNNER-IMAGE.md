# Уменьшенный образ исполнителя скриптов

Дата: 2026-11-15. Собран и проверен на Kali `192.168.56.103`, `linux/amd64`.

## Размеры

Значения `docker image ls --tree gomate-runner`, десятичные МБ:

| Метрика | Исходный `latest` | Новый `slim-test` |
|---|---:|---:|
| DISK USAGE | 789 МБ | 396 МБ |
| CONTENT SIZE | 384 МБ | 78,6 МБ |
| Слой установки Python-зависимостей (`docker history`) | 240 МБ | 154 МБ |

DISK USAGE учитывает хранение содержимого образа и распакованных слоёв.
Экономия около 50% относится к этим двум конкретным образам в хранилище
Docker на Kali. Она складывается из удаления ненужных файлов и различия
в хранении слоёв: новая сборка BuildKit использует сжатые blobs. Это не
означает, что установленное окружение или потребление RAM уменьшились вдвое.
Суммарный размер распакованных слоёв по `docker history` изменился примерно
с 404 до 317 МБ (около 21%). Общие слои нельзя повторно суммировать при
оценке свободного места всего Docker-хранилища.

Исходный ID: `sha256:2bd916bd0c9d6de6e8570e040c40616a3dc7dead209f2b70c6b3354ba53c4fa7`.
Новый ID: `sha256:a492a5039bd130478b1a80bd66cd29808f86869426f8360d408f3a8fda0c842c`.

## Изменения

- `pip --no-compile` исключает предварительную компиляцию `.pyc`.
- Удалён `unicorn/lib/libunicorn.a`, предназначенный для статической линковки
  нативных программ. Python использует сохранённую динамическую библиотеку.
- `strip --strip-unneeded` удаляет отладочные и ненужные символы из нативных
  Python-библиотек. Это уменьшает возможности отладки самих этих библиотек.
- Очистка выполняется в том же Docker-слое, что и установка пакетов.

Все 35 пакетов из `pip freeze` и их версии совпадают в исходном и новом
образах. Bash, curl, binutils, requests и pwntools сохранены. Отсутствие
готового байткода может увеличить время первого импорта; это не проверка
ускорения запуска.

## Проверки

`scripts/test-runner-image.py` прошёл на обоих образах:

- HTTP POST через requests и Bash/curl с побайтовой проверкой ответа;
- TCP через `pwn.remote`, отправка и получение строки;
- чтение ELF, GNU assembler/disassembler, Capstone и исполнение кода Unicorn;
- оба нативных backend zstandard и шифрование/расшифровка AES-GCM;
- запуск от UID 65532 при read-only rootfs, RAM 512 МиБ, CPU 0,5 ядра,
  лимите 64 процессов, без capabilities и с tmpfs `/tmp` 64 МиБ.

Тест использует только loopback внутри одноразового контейнера, `--network
none`. В исходном образе обнаружено ограничение: `pwntools.asm()` требует
отсутствующий `cpp`. Новый образ сохраняет этот набор инструментов;
ассемблер проверяется прямым вызовом `as`, дизассемблер — через pwntools.
Это smoke-проверка основных функций, а не полная регрессия всех API pwntools.

Повторение из корня репозитория:

```sh
docker build -f deploy/runner/Dockerfile -t gomate-runner:slim-test .
docker run --rm -i --read-only --network none \
  --tmpfs /tmp:rw,nosuid,nodev,size=67108864,mode=1777 \
  --memory 512m --cpus 0.5 --pids-limit 64 \
  --cap-drop ALL --security-opt no-new-privileges:true \
  gomate-runner:slim-test python3 - < scripts/test-runner-image.py
```

На Kali сохранён отдельный тестовый тег `gomate-runner:slim-test`.
Рабочий `gomate-runner:latest` и конфигурация запущенного GoMate не менялись.
Базовый тег и транзитивные зависимости не закреплены digest/lock-файлом,
поэтому при последующей сборке размеры и версии могут отличаться.
