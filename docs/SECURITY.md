# Безопасность Gomate

## Сетевая граница и авторизация

По умолчанию приложение слушает `0.0.0.0:65000`. Все маршруты проходят через
одну проверку HTTP Basic Auth до обработки пути: HTML/JS/CSS, API, неизвестные
пути, `/metrics`, `/health/live`, `/health/ready` и WebSocket events/arena.
Без правильного логина и пароля ответ — `401` с `WWW-Authenticate`.
Пустые учётные данные не принимаются. Пример пароля из `.env.example`
не позволяет запустить приложение. Сравнение хешей учётных данных выполняется
за постоянное время. Ответы имеют `Cache-Control: no-store`, `nosniff`,
`X-Frame-Options: SAMEORIGIN` и `Referrer-Policy: no-referrer`.

Basic Auth не шифрует пароль: для недоверенной сети требуется HTTPS reverse
proxy или VPN ([RFC 7617](https://www.rfc-editor.org/info/rfc7617/)). При HTTPS
reverse proxy сохраняйте исходный Host и передавайте Authorization и WebSocket
Upgrade. Ограничьте прямой доступ к 65000 либо задайте `LISTEN=127.0.0.1:65000`,
если proxy расположен на том же хосте. TLS в приложении не настроен.

Запросы с чужим Origin отклоняются, в том числе WebSocket. Изменяющие запросы
с `Sec-Fetch-Site: cross-site` также отклоняются. CLI/farm-клиенты могут работать
без браузерных заголовков, но обязаны передавать Basic Auth.

PostgreSQL опубликован только на `127.0.0.1:65432` и использует свой пароль.
Docker-шлюз слушает `127.0.0.1:65001` и проверяет отдельный случайный Bearer-токен
на всех маршрутах до маршрутизации. Пустой, короткий и примерный токен запрещены.
Публичные API-прокси к этому шлюзу требуют Basic Auth. Не публикуйте шлюз или БД
наружу: Basic Auth относится к публичному HTTP-серверу Gomate, а не к PostgreSQL.

## Модель доверия

Все обладатели общего логина/пароля имеют полные права Gomate, включая
управление контейнерами, просмотр трафика и выполнение скриптов. Разделения ролей
и индивидуального отзыва доступа нет. Endpoint `/api/v2/farm/client-credentials`
возвращает текущему авторизованному клиенту его собственные credentials по POST
для настройки farm-клиента; это намеренная функция.

Docker socket даёт шлюзу широкие права на хосте; `:ro` у mount не ограничивает
команды Docker API. Шлюз предоставляет фиксированный набор операций, а не
универсальный Docker proxy. Runner запускает код с UID 65532, read-only rootfs,
без capabilities, с `no-new-privileges`, ограничениями CPU/RAM/PID и времени.
Ему доступна сеть хоста для повторения запросов: учётные данные Gomate следует
выдавать только доверенным участникам. Это не изоляция для недоверенных арендаторов.

Скрипт установки генерирует независимые 256-битные секреты и `.env` с правами
600. Существующий `.env` сохраняется. Ограничения перебора пароля на уровне IP
нет; используйте случайный пароль и при необходимости лимиты reverse proxy.
После смены пароля пересоздайте приложение: уже открытые WebSocket проверяются
при handshake и должны быть закрыты перезапуском.

## Аудит 2026-11-18

Проверены границы авторизации, маршрутизация, Origin/WebSocket, Docker gateway,
Compose, runner, выдача статики, HTML-рендеринг чата/пакетов и зависимости.
Исправлен анонимный доступ к `/health/live`, добавлен отказ при пустых credentials,
запрет примерных секретов, общий no-store и проверка Origin для всех HTTP-методов.
Обновлены gRPC, protobuf, Axios и транзитивные зависимости, Playwright и Sass.

Регрессионные тесты проверяют отсутствующий/повреждённый/неверный Authorization
для групп маршрутов и HTTP-методов, корректные credentials, чужой Origin,
реальные WebSocket handshakes, а также отказ Docker-шлюза до обращения к Docker.

Проверки: `go test ./...`, `govulncheck ./...`, сборка Vite, JS unit-тесты,
`docker compose config --quiet`, `sh -n scripts/deploy.sh`.
Интеграционные Go-тесты требуют отдельную БД; без неё они пропускаются.
Полный сетевой pentest, сканирование ОС/базовых Docker-образов и Python-зависимостей
runner в этот аудит не входили.

После обновлений `govulncheck` не обнаружил известных уязвимостей.
`npm audit` оставляет 12 записей (5 high, 7 low), происходящих от двух проблем:

- [Picomatch ReDoS](https://github.com/advisories/GHSA-fc5q-39xc-vjpf): инструменты
  сборки Vite/Sass и их зависимости. Исправленной совместимой версии сканер
  не предлагает; автоматический downgrade Vite не применялся. В финальном
  scratch-образе нет Node, node_modules или dev-server. Не собирайте недоверенные
  исходники/шаблоны glob в доверенном окружении.
- [Vue 2 parseHTML ReDoS](https://github.com/advisories/GHSA-5j4c-8p2g-v4jx):
  Vue 2 и зависящие от него пакеты. Vite использует `vue.runtime.esm.js`, шаблоны
  компилируются при сборке, пользовательские шаблоны не компилируются в браузере.
  Удаление зависимости от Vue 2 требует отдельной миграции интерфейса.

В чате HTML отключён в Markdown, изображения отключены, ссылки ограничены
HTTP(S)/mailto; raw payload экранируется перед `v-html`. Это результаты проверки
указанных путей, а не гарантия отсутствия любых XSS или других уязвимостей.
