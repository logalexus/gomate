# Анализ содержимого и пределы

В настройках сервиса включите HTTP decode для HTTP/1.1, HTTP/2 и plaintext gRPC. URL decode и WebSocket включаются отдельно. Исходные восстановленные TCP-байты всегда сохраняются в блоках `kind=""`; декодированные сообщения идут отдельными блоками `http`, `http2-headers`, `http2-body`, `grpc`, `websocket`. UI позволяет выбрать All blocks / Raw bytes / Decoded messages. Размер сессии считает исходные байты; число блоков включает обе формы представления.

HTTP/1.1: Content-Length, chunked, pipelining, HEAD и промежуточные ответы, gzip; URL path/query percent decoding и form-urlencoded. Тела без длины публикуются после завершения соединения. HTTP/2: отдельная HPACK-таблица на направление, HEADERS/CONTINUATION, DATA по stream ID, trailers/RST/GOAWAY. Обычное HTTP/2-тело собирается до END_STREAM, gRPC-сообщения публикуются сразу после получения полного пятибайтного envelope и payload, до закрытия RPC/соединения. Gzip поддерживается для HTTP-тел и gRPC message compression. gRPC metadata содержит RPC path и stream ID; protobuf payload показывается в text/hex без выдуманных названий полей. Дескрипторы protobuf и TLS session keys в этом выпуске не загружаются.

WebSocket: HTTP upgrade, masked/unmasked frames, continuation и control frames. WebSocket extensions (в том числе permessage-deflate), h2c Upgrade, HTTP/2 server push и TLS decryption не реализованы. Для HTTP/2 поддерживается prior-knowledge plaintext; TLS следует завершать перед выбранной точкой захвата.

Ограничения преднамеренные и видимые:

- Protocol input buffer / тело / распакованное сообщение: 256 KiB; HTTP/HPACK header block: 32 KiB; HPACK dynamic table: 4096 bytes; одновременно 128 HTTP/2 streams на соединение.
- Декодированный вывод ограничен на обработку блока и части соединения. Переполнение/повреждённый протокол создаёт `decode-error` и признак `incomplete`; raw bytes остаются доступны. После нарушения синхронизации декодер направления отключается до новой генерации соединения или сброса состояния.
- Состояние анализатора: максимум 4096 соединений / 64 MiB. Вытеснения считаются в `analysis_evictions_total`; следующая часть соединения получает `incomplete`. Активный накапливаемый payload ограничен отдельно глобальным `ACTIVE_BYTES` (64 MiB по умолчанию), очереди имеют свои бюджеты.
- SUBSTRING/SUBBYTES находят совпадения через границы raw-блоков и периодических публикаций. Максимальная строка шаблона — 4096 bytes. Для REGEX используется окно предыдущих 64 KiB плюс текущий блок; это **оконная**, а не неограниченная whole-stream семантика. Якоря и длинные greedy-выражения могут давать иные результаты, чем анализ целого завершённого потока. Для CTF-флагов предпочтительны конкретные ограниченные шаблоны. Начало совпадения в предыдущем блоке отмечается `crossBoundary`.
- Направления не склеиваются между собой. Поиск через отмеченный gap сбрасывается. UDP-датаграммы не склеиваются для поиска. Декодированные сообщения анализируются самостоятельно; данные разных RPC не смешиваются.
- До 256 совпадений одного шаблона и 1024 совпадений на блок; достижение общего лимита отмечается неполнотой.

Lookback сканирует сохранённые raw и decoded блоки, не запускает повторное декодирование старого raw-трафика после изменения настроек сервиса. При создании фиксируются шаблон, верхние ID и временной диапазон. Для выбранных потоков проверяются все их сохранённые блоки. Один job, по 8 блоков за транзакцию, checkpoint и хвосты поиска в той же транзакции; после перезапуска продолжает работу. LIVE имеет приоритет: при большом backlog/остановке прогресса worker делает паузу. Отмена и прогресс доступны через UI и `/api/v2/jobs`.

Kernel BPF синхронно обновляется при изменении сервисов: IPv4 TCP/UDP фильтруется по source/destination port; VLAN, IPv6 и фрагменты проходят в userspace для корректного разбора/учёта. При более 900 сервисах IPv4 TCP/UDP также проходит в userspace, чтобы не превысить лимит cBPF. IP-фрагменты пока учитываются как unsupported. LIVE требует явного Ethernet-интерфейса; published Docker ports и LOCAL_IPS указываются в координатах именно этой точки захвата. Автоматического подключения Docker socket и выбора нескольких интерфейсов нет.

`/api/v2/diagnostics` под той же Basic auth возвращает прогресс конвейера, Go heap/GC/goroutines, статистику пула PostgreSQL и размер БД. Секреты конфигурации в ответ не входят. Потери записи имеют отдельную ограниченную очередь метаданных (4096 соединений): после восстановления БД ранее сохранённая сессия помечается incomplete. Потерянный payload этим не восстанавливается; после исчерпания очереди метаданных часть потерь остаётся видна только глобальными счётчиками.
