# Новый интерфейс gomate

## Трафик: от условий к содержимому

1. Выберите сервис и нажмите нужные **метки шаблонов** над списком сессий. Метки переносятся по строкам; можно выбрать несколько (до 100). Сессия должна содержать **все выбранные шаблоны** (AND). **Избранное** — отдельная переключаемая метка.
2. Выбранные метки отмечены галочкой и цветом: повторный клик снимает выбор. Крестик рядом с сервисом сбрасывает все фильтры. Выбор шаблонов сохраняется в URL. При изменении условий прежняя выбранная сессия закрывается, чтобы её содержимое не выглядело результатом нового отбора.
3. Откройте сессию. При выборе из **Все сервисы** список остаётся общим — открытие сессии не включает дополнительный фильтр её сервиса.
4. Над пакетами отдельно настройте представление: **Все блоки / Исходные байты / Разобранные сообщения**, направление и **Текст / HEX**. Направление фильтрует только загруженную страницу; область действия указана в подсказке и доступном имени поля. Эти переключатели не меняют отбор сессий слева.
5. Для анализа кодированных значений выделите фрагмент и нажмите **Декодировать**. Копирование находится в меню блока. Пункты **Python requests… / curl… / pwntools…** открывают [редактор скрипта](REQUEST_WORKBENCH.md): код можно изменить, скопировать или выполнить на сервере gomate с просмотром stdout/stderr.

**Пауза** останавливает обновление представления сессий и пакетов; сервер продолжает захват. **К новым** возвращает LIVE-представление из истории и снимает паузу. Старые страницы доступны через **Старее / Новее**. Ctrl+↑/↓ переключает сессии; сочетание не перехватывается внутри полей ввода и диалогов.

Плюс рядом с выбором сервиса открывает Docker-поиск/ручное добавление; шестерёнка — настройки выбранного сервиса. На небольшом экране список сессий и содержимое расположены последовательно; метки остаются доступны без раскрытия панели. Если шаблонов много, прокручивается только область меток, оставляя место списку.

## Основные разделы

- **Аномалии:** сводка, карточки сервисов, условия отбора и объяснения находок.
- **Контейнеры:** состояние окружения, поиск и действия; отдельная вкладка логов с выбором источника, периода, поиска и потока. На телефоне строки контейнеров превращаются в карточки.
- **Мониторинг:** CPU, RAM, диск и сеть хоста, таблица ресурсов контейнеров и графики выбранного контейнера. Карточки, числовые значения и шкалы показывают нагрузку: **зелёный < 70%**, **жёлтый ≥ 70%**, **красный ≥ 90%**. Цвет сопровождается подписью и процентом; недоступные метрики остаются нейтральными. Для RAM берётся доля лимита, для диска хоста — доля занятого объёма. В таблице CPU сохраняет Docker-формат (100% = одно ядро), а цвет и шкала рассчитываются от мощности всех ядер хоста: 100% на восьмиядерном хосте — 12,5%. Это доля хоста, а не лимита CPU контейнера. Линии графиков меняют цвет по этим же порогам; фон выделяет верхние диапазоны. Сеть и дисковый ввод-вывод используют отдельные цвета направлений без оценки перегрузки: предел пропускной способности не известен.
- **Чат команды:** общий канал, история и редактор Markdown с предпросмотром. Сохраняются анонимные имена и ограниченный виртуальный список сообщений.
- **Шаблоны:** менеджер с поиском/фильтрами, массовыми действиями и редактором. Условия и тестер расположены рядом; редкие действия строки доступны через **Ещё**.
- **Настройки:** захват, хранение и локальное отображение. Ручное удаление выделено в отдельную зону с оценкой объёма и подтверждением.

Светлая/тёмная тема переключается в правой части общей панели и сохраняется в браузере. Для нового браузера выбрана тёмная тема; ранее сохранённый выбор сохраняется. Нижняя строка показывает состояние capture, счётчики и выполняющийся lookback. Отдельного внешнего подключения за шрифтами интерфейс не требует.

## Визуальная система

Общие цвета, отступы, типографика и состояния вынесены в `web/src/styles/workspace.css`: примитивы → смысловые токены → стили компонентов. Оба режима используют одинаковую структуру и бирюзовый акцент; цвет сопровождается подписью, а не заменяет её. Фокус клавиатуры виден, системное reduced-motion отключает анимации, поля и действия имеют текстовые метки.

Список сессий использует `patternIds` (AND); старые ссылки `?pattern=ID` и API `pattern.id` поддерживаются. Серверный полнотекстовый поиск и фильтр направления по всей истории не добавлены.

В строке сессии показывается путь первого разобранного входящего HTTP/HTTP2/gRPC-запроса, например `/api/login`. Путь хранится вместе с сессией и остаётся после очистки payload. TCP без распознанного HTTP-пути не получает выдуманный адрес. Для старых сессий до обновления путь отсутствует: массовая повторная обработка истории автоматически не запускается.
