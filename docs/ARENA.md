# Пакетная арена

В чате справа в шапке нажмите **Арена**, затем **Войти на арену**. Все участники одного экземпляра gomate попадают на общую карту. Имена совпадают с анонимными именами чата; дополнительных аккаунтов нет. Одна вкладка с игрой на браузер, до 16 игроков одновременно.

Это мини-шутер от первого лица с полноценной 3D-сценой на WebGL: объёмные модели игроков и оружия, перспективная камера, освещение и проверка глубины. На карте есть укрытия; у игрока 100 HP, три попадания до фрага, автоматическое возрождение через 3 секунды. После возрождения действует защита на 1 секунду, которая снимается собственным выстрелом. Кнопка **Счёт** показывает фраги и смерти. Счёт хранится до выхода, вся арена — только в памяти процесса.

- **WASD** или ↑/↓ — движение; **←/→** — поворот.
- Мышь — горизонтальный и вертикальный обзор после клика по сцене. Если браузер не разрешает захват мыши, зажмите **ПКМ** для поворота.
- **ЛКМ** или **Space** — стрельба; можно удерживать.
- **Esc** — отпустить мышь и открыть паузу. Пауза не защищает от попаданий.
- На сенсорном экране доступны кнопки движения, поворота и огня; проводите пальцем по сцене для обзора.
- Закрытие окна возвращает в чат, сохраняя черновик. Скрытие вкладки отключает игрока; для возврата нажмите **Войти на арену**.

## Изоляция от анализатора

Арена не использует БД, очереди захвата, блокировки каталога или SSE/WebSocket-уведомления трафика. Код игры загружается отдельным frontend chunk только при открытии окна. Внешние ресурсы, CDN и новые npm-зависимости не нужны. Требуется поддержка WebGL в браузере; если она недоступна, окно покажет понятную ошибку.

Серверная симуляция идёт 20 раз в секунду, состояния рассылаются 10 раз в секунду. Клиент отправляет ввод с частотой до 20 раз в секунду. Сервер задаёт скорость, столкновения, частоту выстрелов, урон, возрождение и счёт; координаты и результаты попаданий от клиента не принимает. Учитывается вертикальный угол прицела: выстрел выше головы или в пол не наносит урон.

Ограничения: 16 игроков, 256 байт на входное сообщение, до 60 сообщений за секунду на соединение, один ожидающий снимок на клиента, тайм-аут записи 1 секунда и чтения 15 секунд. Через 250 мс без свежего ввода движение и огонь прекращаются. Когда все вышли, таймер симуляции останавливается. Рендер ограничен частотой до 60 кадров/с и шириной 960 пикселей и не использует масштабирование по devicePixelRatio.

Endpoint `GET /api/v2/chat/arena` использует WebSocket, существующий Basic Auth, cookie чата и проверку Origin. Отдельные порты не нужны; обратный прокси должен пропускать WebSocket Upgrade, как для `/api/v2/events`.

Это локальная арена одного Go-процесса: перезапуск сбрасывает игроков и счёт. При нескольких экземплярах приложения понадобится маршрутизация всех участников в один процесс. Компенсации сетевой задержки и матчмейкинга нет.

## Проверки

```
.tools/go/bin/go test -race ./internal/arena ./internal/api
.tools/go/bin/go test ./internal/arena -run '^$' -bench BenchmarkFullRoomTick -benchmem
npm --prefix web run build
node tests/browser/arena.cjs
```

`arena.cjs` запускает отдельный настоящий Go WebSocket-сервер и два браузерных клиента; API чата и анализа подменяются синтетическими ответами. Проверяет движение, бой, счёт, возрождение, паузу, мобильную раскладку, выход и сохранение черновика. `arena-live.cjs` проверяет развёртывание на Kali двумя временными игроками, не публикуя сообщений в чат.
