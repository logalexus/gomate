# Перенос БД Packmate Java

Импортёр рассчитан на схему ревизии `938031f1dedfbedabef5b049368ed5b6ba6a900a`: таблицы `service`, `pattern`, `stream`, `packet`, `found_pattern`, `stream_found_patterns`. Источник открывается с `default_transaction_read_only=on`. Лучше использовать отдельную восстановленную копию `pg_dump`, зафиксированную на время всего импорта.

1. Сделать backup Java-БД. Не менять её схему и не подключать Go к ней как к рабочей БД.
2. Создать отдельную пустую БД для Go и остановить Go-приложение на время импорта. Импортёр создаёт только таблицы с префиксом `gomate_`.
3. Передать подключения через `SOURCE_DATABASE_URL` и `DATABASE_URL` в окружении. Не помещать пароли в командную строку или Git.
4. Собрать и запустить:

```sh
go build -o bin/import-legacy ./cmd/import-legacy
# Только настройки и шаблоны:
bin/import-legacy --source-id game-backup-2026-11-14
# Дополнительно история, совпадения и избранное:
bin/import-legacy --source-id game-backup-2026-11-14 --history
```

Бинарник также входит в Docker-образ как `/import-legacy`; для его запуска переопределить entrypoint и передать обе переменные окружения. `--source-id` — постоянное имя конкретной неизменяемой копии БД, а не пароль. Не переиспользовать его для другой БД. Возобновление после прерывания — той же командой, с тем же источником и ID, при остановленном Go-приложении.

Настройки проверяются до переноса. Неподдерживаемые Java regex в активных шаблонах отклоняются с ID проблемного шаблона: сначала исправить их в копии источника под синтаксис Go/RE2. Включённый legacy TLS также вызывает явный отказ: автоматического тихого отключения нет. Для согласованного переноса без TLS отключить `decrypt_tls` только в копии и учитывать, что последующий захват шифрованного трафика останется шифрованным.

Импорт сохраняет ID и обновляет sequence генераторов. Пакеты переносятся порциями по 8, потоки по 100; прогресс фиксируется вместе с каждой порцией. Первое выполнение требует пустого назначения. Повторное выполнение продолжает перенос, не дублируя уже сохранённые строки. Нельзя параллельно запускать LIVE и импортировать историю с исходными ID. Пакеты Java более 4 MiB вызывают явную ошибку; это ограничение памяти импортёра, а не разрешение отбрасывать историю.

Исторические пакеты имеют `kind=legacy`: содержимое могло быть преобразовано Java-анализатором, поэтому они не выдаются за оригинальный сетевой payload. Поля client/server отсутствуют в старой схеме и получают значение `legacy`. Перед переключением сравнить количество потоков/пакетов/избранного, несколько payload и совпадений. Тест этого пути находится в `tests/integration/import_test.go`; импорт реальной пользовательской БД ещё не выполнялся.

Для отката остановить Go и вернуть прежний Compose с неизменённой Java-БД. Новая история Go не появляется в Java автоматически. Перед обновлением Kali-стенда создан `~/gomate-test/backups/before-features.dump`.
