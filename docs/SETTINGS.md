# Настройки через UI

## Захват

Откройте **Настройки → Захват трафика**. Список берётся с хоста, поскольку Compose запускает анализатор с `network_mode: host`. Рядом с именем указаны IP и причина недоступности. Поддерживаются поднятые Ethernet-интерфейсы; loopback, `any` и другие link types не поддерживаются.

Выберите интерфейс, включите LIVE и нажмите **Сохранить и применить**. По умолчанию локальные IP определяются автоматически. Для нестандартной точки захвата их можно задать вручную. При смене интерфейса старые потоки завершаются, затем запускается новый reader; возможен короткий разрыв захвата. Неверные параметры или ошибка открытия нового интерфейса оставляют текущий захват работающим. Смена только срока хранения не перезапускает reader.

Настройки сохраняются в PostgreSQL. `INTERFACE`, `LOCAL_IPS`, `RETENTION` задают только первоначальные значения. Конфликт изменений из двух вкладок возвращает ошибку версии: закройте и заново откройте настройки. При исчезновении сохранённого интерфейса UI остаётся доступным для выбора другого. Эти настройки предназначены для LIVE; режим PCAP ими не управляется.

## Сервисы из Docker

**+ Сервис → Docker** показывает запущенные контейнеры, имя, образ и опубликованные порты. Поиск фильтрует список; «+» добавляет выбранный порт, уже добавленные отмечаются. Если контейнер имеет несколько портов, каждый добавляется отдельно. Управляющие контейнеры gomate исключены из списка. Обновление списка выполняется при открытии и кнопкой обновления.

Для внешнего интерфейса выбирайте опубликованный порт хоста. Порты без публикации и host-network без явного списка портов нельзя достоверно обнаружить через Docker API — используйте ручное добавление. Список отражает публикацию Docker, а не результат проверки доступности приложения. После добавления можно включить HTTP decode (в том числе HTTP/2/gRPC), URL decode и WebSocket в редакторе сервиса. Сам протокол по номеру порта не угадывается.

В Compose добавлен отдельный шлюз `discovery`, имеющий доступ к Docker socket. Основной процесс анализатора socket не получает. Шлюз слушает `127.0.0.1:65001`, предоставляет аутентифицированные фиксированные маршруты discovery, списка контейнеров, ограниченных логов и start/stop/restart/pause/unpause. Удаления контейнеров, exec и произвольного проксирования API нет. Подробности — [CONTAINERS_CHAT.md](CONTAINERS_CHAT.md). Общий случайный `DOCKER_DISCOVERY_TOKEN` длиной от 24 символов задаётся в `.env`, через UI не возвращается. При недоступности Docker остаётся ручное добавление.

## Хранение и очистка

В **Настройки → Хранение и очистка** задаются независимо:

- Возраст содержимого пакетов по времени блока. `0` отключает отдельную очистку payload; удаление сессии всё равно удаляет содержимое.
- Возраст сессии от её последнего трафика. `0` отключает автоматическое удаление сессий.
- Интервал фоновой очистки: от 5 секунд до часа.
- Сохранение избранных сессий и их содержимого.

Ненулевой срок хранения содержимого не должен превышать ненулевой срок сессий. Максимум — 90 дней. Очистка выполняется небольшими транзакциями с ограничением времени. Она освобождает место для повторного использования PostgreSQL; файл БД не обязан сразу уменьшаться на диске.

Для ручной очистки выберите **только содержимое** или **сессии с содержимым**, область сервиса и сохранение избранного. Нажмите **Оценить объём**, затем **Удалить…** и подтвердите действие. Оценка приблизительная: захват продолжается. Задание фиксирует границы уже записанных данных, новые пакеты после запуска сохраняются. Поэтому активная сессия с новым трафиком может остаться даже при удалении сессий. Удалённое содержимое отмечается в списке сессий; метаданные и найденные ранее шаблоны при очистке только содержимого остаются.

Одновременно выполняется одно ручное задание; прогресс сохраняется в БД и переживает перезапуск. **Остановить** прекращает дальнейшие порции, уже удалённые данные не восстанавливает. Настройка избранного для ручного задания независима от автоматической очистки.

## Шаблоны поиска

Кнопка **Шаблоны** открывает отдельный менеджер. Доступны поиск по имени/значению/группе, фильтры группы, сервиса, статуса и действия, страницы по 20 шаблонов. **Выбрать найденные** выбирает все результаты текущего фильтра, включая другие страницы. Массовые действия: включить, выключить, удалить; API принимает до 1000 шаблонов за раз. У каждой строки есть переключатель, редактирование, копирование, поиск в прошлом и переход к найденным сессиям.

Редактор позволяет выбрать текст, HEX или regex, направление, сервис, FIND/IGNORE, группу и цвет. Пресеты помогают начать, а **Проверить** запускает тот же серверный matcher на фрагменте текста или HEX и показывает совпадения. Максимальный пример — 16 KiB. Regex использует Go RE2: обратные ссылки и lookaround не поддерживаются. Полная семантика поиска описана в [PROTOCOLS.md](PROTOCOLS.md).

Правила применяются к новому трафику сразу. Изменение условия создаёт новую версию с новым ID, чтобы старые совпадения не приписывались другому выражению. Изменение имени, цвета, группы или состояния сохраняет ID. **В прошлом** отдельно запускает поиск по сохранённому содержимому; после очистки payload повторный поиск по нему невозможен.
