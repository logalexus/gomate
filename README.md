# Packmate Go / gomate

Go-реализация основных LIVE-сценариев Packmate со знакомым Vue-интерфейсом. Захватывает TCP/UDP, разбирает HTTP/gzip, HTTP/2/gRPC и WebSocket, выполняет потоковый поиск и lookback, переносит настройки и историю Java-версии. **Приёмка длительной работы под соревновательной нагрузкой ещё не завершена.** План — [PLAN.md](PLAN.md), динамические настройки — [docs/SETTINGS.md](docs/SETTINGS.md), проверки UI — [reports/DYNAMIC_UI.md](reports/DYNAMIC_UI.md), протоколы — [reports/FEATURES.md](reports/FEATURES.md), ранние результаты — [reports/INITIAL.md](reports/INITIAL.md).

## Что работает

- LIVE через Linux AF_PACKET/TPACKET_V3; чтение обычного PCAP для разработки.
- TCP reassembly, обработка перестановки/повторной передачи сегментов, признаки пропущенных данных; открытые соединения публикуются частями примерно раз в секунду.
- Шарды потоков, общий бюджет активного payload, ограничения активных соединений и очередей по количеству/байтам; динамический BPF по портам. Capture не ожидает запись в БД; перегрузка отражается в счётчиках потерь.
- Пакетная атомарная запись метаданных и `COPY` payload. Повтор транзакции после неопределённого результата commit не дублирует данные.
- HTTP/1.1 (gzip/chunked/pipelining), HTTP/2 (HPACK/multiplexing), plaintext gRPC (unary/streaming/gzip), WebSocket. Raw bytes и decoded сообщения сохраняются отдельно; подробные пределы — [docs/PROTOCOLS.md](docs/PROTOCOLS.md).
- Lookback с persistent checkpoint, прогрессом и отменой; импорт настроек, истории и избранного из Java-БД — [docs/MIGRATION.md](docs/MIGRATION.md).
- Декодер выбранного трафика: автопоиск JWT/Base64 и ручные URL, HEX, JSON; цепочки преобразований, копирование и отмена в браузере — [docs/TRAFFIC_DECODER.md](docs/TRAFFIC_DECODER.md).
- Вкладка контейнеров: статус, запуск/остановка/перезапуск/пауза, ограниченный LIVE-просмотр логов с фильтрами и виртуализацией. Общий анонимный чат с историей в БД — [инструкция](docs/CONTAINERS_CHAT.md).
- Динамический выбор интерфейса, автоматические локальные IP, добавление опубликованных Docker-сервисов через «+»; настройки сохраняются в БД.
- Вкладка «Аномалии»: сессии, непохожие на обычный трафик сервиса (новые эндпоинты и поля, необычные символы, форма и длина значений, ответы), и кража флагов без опоры на IP. Без нейросетей, модель учится на живом трафике — [docs/ANOMALY.md](docs/ANOMALY.md).
- Менеджер шаблонов: группы, поиск, фильтры, массовые действия, копирование, полный редактор и проверка на примере. FIND/IGNORE, избранное, cursor pagination, base64 payload, строковый/байтовый/regex-поиск.
- Отдельные сроки хранения содержимого и сессий, защита избранного, ручная очистка с оценкой объёма и отменой задания.
- Единый адаптивный Vue-интерфейс со светлой/тёмной темой, явными активными фильтрами, виртуальным списком сессий и отдельными настройками представления пакетов — [инструкция](docs/UI_GUIDE.md). Native WebSocket отправляет объединённые уведомления об изменениях; клиент перечитывает состояние после переподключения и периодически проверяет его.
- Метрики потерь/очередей/прогресса, readiness с проверкой БД, ограниченные повторы записи, очистка старых потоков с сохранением избранного.

## Запуск через Docker Compose

Нужны Linux, Docker Engine и Compose v2. Для сборки используются Go 1.27 и Node 20; на хосте они не требуются.

```sh
cp .env.example .env
# Задать разные случайные DB_PASSWORD, WEB_PASSWORD и DOCKER_DISCOVERY_TOKEN в .env.
# DOCKER_DISCOVERY_TOKEN: не менее 24 символов.
# Интерфейс можно выбрать после запуска в UI → Настройки.
docker compose up --build -d
```

В этой рабочей папке `.env` уже создан с локальными случайными паролями и исключён из Git. `INTERFACE`, `LOCAL_IPS` и `RETENTION` инициализируют настройки только при первом запуске. Затем настройки из БД меняются через UI. Добавьте сервис через «+ Сервис» → Docker или вручную. Порт задаётся относительно точки захвата: для внешнего интерфейса это опубликованный порт хоста.

По умолчанию UI доступен на `http://127.0.0.1:65000`, БД — только на `127.0.0.1:65432`. Логин по умолчанию `packmate`, пароль берётся из `.env`. Для доступа с другого компьютера можно использовать SSH port forwarding. `LISTEN` настраивается явно.

При первом запуске с пустым `INTERFACE` приложение открывает UI/API без захвата: выберите интерфейс и включите LIVE в настройках. Выбирать интерфейс автоматически опасно для корректности анализа: одновременный захват внешнего интерфейса и Docker bridge может дублировать трафик. Текущий LIVE-адаптер рассчитан на Ethernet; `any` не поддерживается. Неподдерживаемые интерфейсы показаны неактивными. Docker-discovery предлагает опубликованные TCP/UDP-порты; host-network и неопубликованные порты требуют ручной настройки. Сопоставление произвольной Docker/NAT-топологии не реализовано.

Compose ограничивает Go-контейнер 1 CPU / 2 GiB, PostgreSQL — 1 CPU / 2 GiB; это начальный общий бюджет 2 CPU / 4 GiB на машине с игровыми сервисами. Его достаточность для конкретной игры пока не подтверждена. БД имеет постоянный volume, начальный срок хранения сессий — 1 час, далее он настраивается через UI. Размер диска и свободное место необходимо учитывать отдельно.

```sh
docker compose logs --tail=100 app
docker compose down       # данные PostgreSQL сохраняются
```

## Локальная разработка

```sh
make build GO=.tools/go/bin/go   # или make build, если go установлен в PATH
cd web && npm ci && npm run build && cd ..
docker compose up -d --wait db
python3 scripts/run-dev.py
```

`.tools/go` — локальная установка компилятора в текущем workspace; в Git она не входит. В другом окружении установите Go 1.27+. Для dev-server фронтенда: `cd web && npm run serve`; Vite проксирует `/api` в локальный Go API.

Важные настройки окружения:

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `DATABASE_URL`, `WEB_PASSWORD` | обязательны | Подключение к отдельной Go-БД и HTTP Basic auth |
| `INTERFACE`, `LOCAL_IPS` | пусто | Начальные LIVE-интерфейс и IP; при пустом LOCAL_IPS адреса берутся с интерфейса |
| `DOCKER_DISCOVERY_TOKEN` | обязателен в Compose | Отдельный секрет шлюза Docker-discovery |
| `PCAP_FILE` | пусто | Тестовый PCAP; взаимоисключается с `INTERFACE` |
| `SHARDS` | 2 | Обработчики соединений |
| `MAX_FLOWS` | 4096 | Общий предел активных соединений |
| `MAX_FLOW_BYTES` | 262144 | Предел накапливаемого payload перед публикацией части |
| `ACTIVE_BYTES` | 64 MiB | Общий бюджет накапливаемого payload активных соединений |
| `QUEUE_PACKETS`, `QUEUE_BYTES` | 2048 на шард, 32 MiB суммарно | Ограничения очередей входа |
| `WRITE_BYTES` | 64 MiB | Бюджет очереди записи; также максимум 4096 частей |
| `FLUSH_INTERVAL`, `IDLE_TIMEOUT` | 1s, 40s | Публикация частей и освобождение неактивных потоков |
| `DB_TIMEOUT` | 3s | Предельное время одной операции с БД |
| `RETENTION` | 1h | Начальный срок хранения сессий; далее управляется из UI |

`/metrics`, `/health/ready` и `/api/v2/snapshot` защищены HTTP Basic auth. `/health/live` сообщает только о работоспособности HTTP-процесса. Счётчики `*_drops_total` различают kernel/capture, очередь входа, лимит потоков и запись; у них разные единицы, суммарный индикатор UI называется «Loss events», а не числом потерянных пакетов.

При недоступной БД writer делает максимум три попытки с deadline, затем учитывает потерянные части и продолжает работу. Никакого скрытого бесконечного накопления на диске нет. Данные до commit не имеют гарантии сохранности; дисковый spool пока отсутствует.

## Тесты

```sh
make test GO=.tools/go/bin/go
python3 scripts/test-integration.py
java scripts/RegexProgress.java
```

Интеграционные тесты используют отдельную БД **gomate_test** и очищают только её таблицы. Они проверяют API, idempotency, pagination и retention. `scripts/test-integration.py` запускает также Go race detector. Java-пример ограниченно воспроизводит отсутствие продвижения при пустом regex-совпадении в алгоритме исходного Packmate; он не утверждает, что именно это вызвало наблюдавшиеся пользователем зависания.

Изолированный LIVE-стенд (нужны свободные локальные порты 16500 и 18080):

```sh
python3 scripts/live-setup.py
python3 scripts/live-bench.py --rps 200 --seconds 30
python3 scripts/live-bench.py --rps 1000 --seconds 30
python3 scripts/fault-smoke.py
```

Генератор и тестовый HTTP-сервис обмениваются только тестовыми данными. Анализатор наблюдает `eth0` сетевого namespace контейнера `gomate-fixture`; реальные интерфейсы машины в этом тесте не захватываются. Тестовые контейнеры называются `gomate-fixture` и `gomate-live-test`, БД — `gomate_live`. В нагрузке 200 логических IDs атакующих, а не 200 отдельных машин. Отчёт проверяет уникальные маркеры ответов в БД и фактически поданную нагрузку.

`fault-smoke.py` на 5 секунд приостанавливает **только PostgreSQL этого Compose-проекта** и возобновляет его в `finally`. Не запускать такой эксперимент на экземпляре, который уже используется для игры.

Браузерная проверка после наполнения LIVE-стенда:

```sh
cd web && npx playwright install chromium && cd ..
node tests/browser/smoke.cjs
# При наличии совместимого Chromium: CHROMIUM_PATH=/path/to/chrome node tests/browser/smoke.cjs
```

Удаление только временных fixture-контейнеров, без удаления БД:

```sh
docker stop -t 20 gomate-live-test gomate-fixture
docker rm gomate-live-test gomate-fixture
```

## Проверенные границы

- Первый LIVE-релиз предназначен для plaintext трафика на явно выбранном Ethernet-интерфейсе. TLS decryption, WebSocket extensions, HTTP/2 server push/h2c upgrade и IP defragmentation не входят в реализованный набор. Шифрованное содержимое не выдаётся за декодированное; неподдержанные/усечённые сообщения отмечаются явно.
- gRPC получает RPC path, stream ID, границы сообщений и gzip-декодирование. Названия protobuf-полей без схем не восстанавливаются.
- Поиск SUBSTRING/SUBBYTES проходит через границы raw-блоков; regex имеет явно ограниченное окно 64 KiB. Детали семантики и всех бюджетов — [docs/PROTOCOLS.md](docs/PROTOCOLS.md).
- Импортёр проверен на синтетической схеме исходной Java-ревизии; перенос пользовательской БД не выполнялся. Используйте неизменяемую копию источника и остановленное пустое назначение.
- `/api/v2/diagnostics` дополняет метрики данными Go runtime/пула/размера БД. Потерянный до commit payload не восстанавливается; ограниченная очередь метаданных помогает пометить затронутые сессии после восстановления БД.
- Замена старого SockJS — native WebSocket + snapshot. Исходный неизменённый frontend не является поддерживаемым клиентом этой версии.
- Шестичасовой soak, сравнение Java/Go и подтверждение SLO на 8 CPU / 16 GiB остаются отдельной приёмкой. Более высокая нагрузка на VM-стенде пока вызывает ошибки/пропуски генератора; отсутствие drops анализатора не означает успешный тест всей системы.

Дополнительные воспроизводимые проверки на разрешённом Kali-стенде:

```sh
python3 scripts/verify-features.py
python3 scripts/remote-bench.py --count 1000 --rps 100 --tag mixed300
node tests/browser/features.cjs
```

`verify-features.py` отправляет тестовый трафик с этой машины на реальные интерфейсы Kali, проверяет декодированные ответы и lookback через SQL и API. `features.cjs` открывает 20 браузерных контекстов и проверяет виртуализацию, gRPC-представление, hex/text и reconnect. Эти проверки используют только специально развёрнутые моки.

Отдельный удалённый тестовый стенд с HTTP, TCP и настоящим gRPC описан в [deploy/kali/README.md](deploy/kali/README.md). Он запускается только по явному разрешению пользователя; инструкции доступа и воспроизводимых проверок находятся там.

Исходные ревизии записаны в [docs/upstream.json](docs/upstream.json). Сохранено уведомление об авторстве Packmate в [LICENSE](LICENSE); `web/` происходит из закреплённого frontend-submodule.
